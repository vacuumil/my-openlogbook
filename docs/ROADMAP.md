# План развития OpenLogBook

Состояние на ноябрь 2026. Есть лётная книжка с офлайн-синхронизацией, карта маршрутов, статистика, допуски по типовому рейтингу, рабочее время по сменам с разбором плана Аэрофлота, ежедневные бэкапы. Нет HTTPS на проде, миграций базы, восстановления пароля и мобильного приложения в магазинах.

Пункты внутри этапа идут по приоритету. Оценки даны для одного разработчика.

## Этап 0. Выпустить то, что уже сделано (1–2 дня)

Без этого новые функции не доходят до пилотов, а офлайн-режим, главное обещание продукта, на проде не работает.

1. **Домен и HTTPS** через `docker-compose.https.yml`. После этого заработают установка на телефон, офлайн-режим и push-уведомления.
2. **Деплой из git** по `docs/DEPLOYMENT_GUIDE.md` вместо архивов. Удалить `scratch/` и старые архивы, сменить пароли SSH, базы и администратора, вход на сервер только по ключу.
3. **Проверка бэкапов**: первый файл в `db-backups`, пробное восстановление на копии, регулярная выгрузка копий с сервера.
4. **Мониторинг доступности** (UptimeRobot или аналог на `/api/health`) и уведомление о падении.

## Этап 1. Надёжность и безопасность (1–2 недели)

1. **Миграции схемы (Alembic).** Зафиксировать текущую схему как базовую ревизию, убрать `create_all` и скрипты ручных миграций. Любое следующее изменение таблиц без этого рискованно.
2. **Восстановление пароля по почте.** Сейчас забытый пароль может сбросить только администратор. Нужны письмо со ссылкой на одноразовый токен с коротким сроком, подтверждение почты при регистрации, ограничение частоты запросов.
3. **Сессии.** Токен в `localStorage` на 30 дней заменить на короткий токен доступа и обновляемый токен в `httpOnly`-cookie. Добавить список активных устройств и выход со всех.
4. **Журнал событий** входов, смены пароля и действий администратора.
5. **Двухфакторный вход по TOTP**, по желанию пользователя.
6. **Ошибки фронтенда** собирать в Sentry или самописный эндпоинт, чтобы видеть падения у пилотов.
7. **Тесты интерфейса.** Сейчас покрыты логика и API, но не экраны. Нужны сквозные тесты Playwright на вход, добавление рейса, офлайн-синхронизацию и импорт плана.
8. **Доступность**: подписи полей, фокус и клавиатура в модальных окнах, контраст. Разбить `AddFlightModal` (1600+ строк) на части.

## Этап 2. Рабочее время и зарплата (2–3 недели)

Самое ценное для пилота направление после лётной книжки.

1. **Форматы планов.** Разбор плана Аэрофлота уже есть. Добавить другие авиакомпании (S7, Победа, Россия, Уральские) по образцам PDF, iCal-ростеры (AIMS, Jeppesen, NetLine) и распознавание сканов через OCR.
2. **Факт против плана.** Сверка плана с внесёнными рейсами: что отменено, что добавлено, где задержки.
3. **Нормы рабочего времени по-настоящему.** Таблица максимальной полётной смены по времени явки и числу участков (ORO.FTL.205), отдых вне базы, накопленные лимиты за 7, 14 и 28 дней. Отдельный режим для российских норм (приказ Минтранса № 139), так как они отличаются от EASA.
4. **Зарплатные правила.** Шаблоны оплаты: оклад, ставки по типу ВС и должности, ночные, праздничные, командировочные, резерв по разным ставкам. Ежемесячный расчётный лист и сравнение с фактической выплатой.
5. **Отчёт для бухгалтерии** в XLSX с итогами по месяцам и за год.
6. **Перенос смены через месяцы**, чтобы проверка отдыха видела последнюю смену прошлого месяца.

## Этап 3. Лётная книжка как основной инструмент пилота (3–4 недели)

1. **Быстрый ввод**: «повторить рейс», шаблоны частых маршрутов, автоматическое время блок-налёта и ночи из плана.
2. **Импорт из плана в книжку**: распознанный месячный план превращать в черновики рейсов, которые после полёта нужно только подтвердить.
3. **Официальные форматы печати**: страницы в формате EASA FCL.050 и книжки установленного образца РФ с переносом итогов между страницами, подписью и печатью.
4. **Тренажёрные сессии и наземная подготовка** как отдельный тип записи, без попадания в налёт.
5. **Многоэкипажный учёт**: КВС, второй пилот и инструктор с автоматическим разделением времени.
6. **Полный журнал изменений записи**: кто и когда исправил рейс. Это важно для доверия при проверках.
7. **Вложения**: фото бортжурнала, скан задания на полёт.

## Этап 4. Допуски и сроки (1–2 недели)

1. **Свой набор правил допуска**: администратор авиакомпании или сам пилот задаёт, какие типы входят в рейтинг и какие требования действуют.
2. **Учёт взлётов, посадок до полной остановки, IR и тренажёра**, чтобы расчёт по EASA и FAA был точным, а не оценочным.
3. **Напоминания** о сроках ВЛЭК, LPC, OPC, паспорта и визы push-уведомлениями и письмами за 90, 30 и 7 дней.
4. **Календарь сроков** с экспортом в Google и Apple Calendar.

## Этап 5. Мобильные приложения и офлайн (3–4 недели)

1. **Нативная оболочка (Capacitor)** для публикации в RuStore, App Store и Google Play: надёжные уведомления, фоновая синхронизация, вход по биометрии.
2. **Офлайн-карта**: кэширование тайлов для часто летаемых регионов.
3. **Виджет** на главном экране с налётом за 28 дней и ближайшим сроком.
4. **Шифрование локальной базы** на устройстве.

## Этап 6. Аналитика и полезные данные (2–3 недели)

1. **Отчёт за год**: итоги, рекорды, новые аэродромы, карта года. Его можно делить с коллегами.
2. **Прогноз лимитов**: сколько ещё можно налетать до лимитов при текущем плане.
3. **Погода по маршруту** из плана на ближайшие сутки.
4. **Сравнение с прошлыми годами** по месяцам на одном графике.

## Этап 7. Продукт для команды и авиакомпаний (1–2 месяца)

1. **Организации**: авиакомпания или лётный отряд с пилотами, командирами эскадрилий и правами доступа.
2. **Панель командира**: допуски и сроки своих пилотов, лимиты рабочего времени. Только с согласия пилота.
3. **Интеграции**: API для загрузки планов из систем авиакомпании, выгрузка в АИС.
4. **Модель монетизации**: бесплатно для пилота, платно для организаций. Вместе с ней понадобятся юридическая база: политика конфиденциальности, хранение персональных данных в РФ по 152-ФЗ, договор-оферта.

## Сквозные задачи

- **Дизайн-система**: единые компоненты кнопок, карточек, полей и модальных окон вместо повторяющихся классов.
- **Переводы**: интерфейс на английском для иностранных пилотов.
- **Документация для пилота**: короткие подсказки внутри приложения и страница помощи.
- **Обратная связь**: форма «сообщить об ошибке» с отправкой технического контекста.
